# Web Speech 懒验证设计

日期: 2026-07-11
状态: 已确认，待实施
关联: `docs/superpowers/specs/2026-07-11-mokuro-speech-and-reading-continuity-design.md`

## 问题

当前实现要求用户手动点击“验证音色”，然后串行验证全部 Edge 日语候选。每个候选都等待真实 `onstart`，失败项最多等待 5 秒；多个失效在线音色会让首次等待按候选数累加。

根因是把“保证已验证列表”做成了全量前置步骤。浏览器只能通过实际合成判断音色能否工作，但没有必要在用户使用前验证所有音色。

## 目标行为

1. 删除手动“验证音色”按钮。
2. 首次选择文本朗读时，直接尝试当前/默认日语音色；这次真实朗读本身完成验证。
3. 用户在下拉框选择具体音色时，只对该音色执行一次短静音验证。
4. 验证成功后采用该音色；失败后从本会话候选列表移除，保持或回退到可用音色。
5. 正式朗读失败时继续移除失败项，并按候选顺序尝试下一个，直到成功或候选耗尽。
6. `canceled` / `interrupted` 不判定为音色失败。
7. 不把验证结果写入 localStorage；浏览器重启后重新按需判断。

## 状态

`useSpeech` 维护三类状态：

- `voices`：浏览器注册的全部音色。
- `candidateVoices`：日语且未在本会话失败的音色；下拉框显示它们。
- verified URI set：本会话已经收到 `onstart` 的音色，用于自动模式优先选择。
- unavailable URI set：出现合成错误或启动超时的音色，从候选列表移除。
- `validatingVoiceURI`：当前被用户选择并静音验证的 URI；用于暂时禁用选择器。

候选不等于已验证。懒验证的取舍是：一个尚未使用的失败音色可能暂时出现在列表中，但它一旦被选择就会验证并移除；不再用长时间全量等待换取首次列表纯净。

## 选择与回退

自动朗读的尝试顺序：

1. 用户已选择且仍为候选的 URI。
2. 本会话已验证的同语言音色。
3. 其余候选中的最佳语言匹配。
4. 当前尝试失败时，从剩余候选继续。

`validateVoice(uri)` 只查找对应候选，用短日文 `あ`、`volume=0` 调用现有 utterance 生命周期。成功返回 true 并加入 verified；失败返回 false 并加入 unavailable。用户切回“自动”不需要验证。

Reader 的 onChange 在 URI 验证成功后才提交 `voiceURI`；失败时保留当前选择并显示现有无可用音色提示。验证期间 select 禁用，但不会影响页面其他操作。

## UI

Mokuro 语音设置保留音量图标、音色标签和 select：

- 初始化后 select 立即显示日语候选，不要求刷新。
- 移除 `RefreshCw` 按钮和 `verifyVoices` 文案。
- 选择验证期间 select 禁用；候选失败后对应 option 消失。
- 没有候选时 select 禁用并保留“自动”占位。

## 测试

纯函数测试新增：

- candidate voices 只保留日语并排除 unavailable，不要求 verified。
- 自动顺序优先指定候选，其次已验证候选，再到普通候选。
- 失败候选移除后回退不会再次选择它。

浏览器验收：

1. Mokuro 模式不显示手动验证按钮。
2. 日语候选加载后 select 可直接操作。
3. 首次点文本无需预操作即可触发朗读。
4. 切换某个音色只验证该项，UI 不进入全量长等待。
5. 失败项移除并回退，取消操作不移除。
6. `npm test`、`npm run lint`、`npm run build`、`git diff --check` 通过。
