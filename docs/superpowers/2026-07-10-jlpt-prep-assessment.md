# JLPT 备考能力评估与提升规划(底稿)

日期: 2026-07-10
状态: 评估底稿 / 待据此推进开发

## 一、评估背景

本评估针对 `manga_learnjp` 项目,从 **JLPT(日本语能力测试,N5–N1)备考** 视角审视当前能力缺口与提升优先级。结论基于对 `src/` 全量代码的审查:AI 提示词与服务层、UI 组件、数据持久化、依赖清单。

项目当前定位是 **漫画阅读 + 按需 AI 讲解工具**,在「真实语境下的词汇/语法习得」这条线上有天然优势--这恰好契合 JLPT 读解与词汇的语境记忆。但作为「结构化备考平台」它还缺很多块。

## 二、现状:JLPT 相关能力盘点

### 已具备

| 能力 | 位置 | 说明 |
|---|---|---|
| 词汇 JLPT 难度标注 | `src/lib/types.ts:6`、`MokuroAnalysisPanel.tsx:18-27` | `WordAnalysis.difficulty` 支持 N5–N1,面板用彩色 badge 显示 |
| N5 过滤(隐藏基础内容) | `client-api.ts:20`(默认 `excludeN5=true`)、`src/lib/analysis-filters.ts` | API 端默认排除 N5;UI 端再过滤 N5/初级词汇与 は/が/を/です/ます 等基础语法 |
| 逐块词汇+语法讲解 | `MokuroAnalysisPanel.tsx` | 读音、释义、词性、例句,但**仅展示** |
| TTS 朗读 | `useSpeech.ts`、`src/lib/speech.ts` | 浏览器 Web Speech API,朗读 OCR 文本块 |
| 分析缓存(重展示) | `MokuroReader.tsx` 的 `persistPageCache` | 仅用于重新展示,**不是学习记录** |

### 完全缺失(对「结构化备考」而言)

- 间隔重复(SRS)/ 闪卡 / 复习系统
- 个人词汇本 / 生词库 / 收藏 / 个人词典
- 语法点库(可按级别浏览的参考库)
- 汉字练习 / 汉字拆解 / 笔顺 / 汉字 JLPT 级
- 听力理解训练(现有 TTS 仅单向朗读,无听写/选择题)
- 模拟测验 / 测验 / 练习 / 题型训练
- 进度跟踪 / 统计 / 学习历史
- 句子上振假名(ruby)渲染(读音现为词汇元数据,不叠加在原文上)
- Anki / CSV 导出
- 用户账号 / 跨设备同步(仅 localStorage + 目录缓存)

依赖侧印证:`package.json` 无 `kuroshiro`/`wanakana`(假名注音)、无 `kuromoji`/`mecab`(形态分析,现全靠 LLM 分词)、无 Anki 库、无数据库/ORM、无 auth。

## 三、地基问题:`difficulty` 字段不可靠

这是后续多项改进的前置依赖,必须先认清。

- **完全由 LLM 生成,无字典校验**:`difficulty` 取值是模型自由返回的,`validateAnalysisResult`/`validateMangaAnalysisResult` 都不校验该字段取值。
- **4 套 prompt 标注方式不统一**:
  - `ANALYSIS_PROMPT`、`LINGUISTIC_ANALYSIS_PROMPT` 要求用 N4–N1
  - `MANGA_PANEL_ANALYSIS_PROMPT`、`CONCISE_MANGA_PANEL_ANALYSIS_PROMPT`、`improved-text-detection.ts` 只用 beginner/intermediate/advanced 三档,**根本不产出 N 级标签**
- **多入口硬编码 `excludeN5=true`**:`analyzeImageForReading` 在两个 service 里都硬编码 `getLearningLevelInstruction(true)`,与调用方无关。
- **颜色映射不统一**:`TextAnalyzer`/`MangaAnalyzer`/`DIFFICULTY_COLORS` 只认三档,N5–N1 落到 default 灰色;只有 `MokuroAnalysisPanel` 认全 8 档。

**结论**:项目声称的那个 JLPT 功能(难度标注)本身不可信,无法支撑真正的分级学习规划。任何依赖「级别过滤」的后续功能都要先把这个地基修牢(接带 JLPT 标签的词库校准)。

## 四、提升点分级(按「备考影响 × 实现成本」)

### 第一梯队(填补核心缺口,性价比最高)

1. **目标级别 + 级别感知过滤**:把现在二元的「显示/隐藏 N5」换成「我的目标是 N3」--N3+ 标为重点新词、N5/N4 折叠为已知。JLPT 备考者最需要「按我的级别筛」。是 `excludeN5` 机制的自然升级。
2. **个人词汇本 + SRS 复习**:目前看过的词用完即弃、零留存。SRS 是词汇 retention 影响最大的单一功能。从「一键加入生词本」起步,再上简单间隔复习。
3. **Anki / CSV 导出**:JLPT 学习者绝大多数在用 Anki。把分析出的词汇导出 CSV/.apkg,是连接「阅读->记忆」的廉价高价值桥梁。当前代码**完全没有**任何导出能力。

### 第二梯队(高价值,中等成本)

4. **用真实字典校验 JLPT 标注**:接入带 JLPT 标签的词库(JMdict + JLPT 标签,或分级汉字/词汇表)校准 LLM 输出,修掉地基问题。没有这步,上面的级别过滤可信度都打折扣。
5. **汉字拆解 + JLPT 汉字级**:JLPT 重考汉字,漫画常带假名注音,但 app 不拆字、不关联 JLPT 汉字级、无汉字复习。可补 kanji -> 部首/笔顺/JLPT 级。
6. **语法点库**:现在语法点只在每块孤立展示,从不聚合成可按级别浏览的参考库。收集起来做「按 N 级浏览的语法索引」对备考有用。
7. **句子上振假名(ruby)渲染**:现读音作为词汇元数据单列,未在原文句子叠加 `<ruby>` 注音,对读解练习帮助有限。

### 第三梯队(更完整,成本更高)

8. **听力理解训练**:JLPT 聴解是大头,现仅 TTS 单向朗读,无听力理解题。可基于 TTS + 现有文本做听写/选择训练。
9. **读解题 / 模拟测验**:JLPT 読解有特定题型(上下文、细节、同义替换、逻辑),现只给翻译,不生成理解性检测。
10. **学习进度统计 / 用户账号 / 云同步**:现仅 localStorage + 目录缓存,无学习历史、无账号、无跨设备同步。

## 五、推荐开发路线

若只挑一个起点,选 **「目标级别设置 + 个人词汇本 + Anki 导出」** 组合:

- 直接补上 JLPT 备考最缺的「记忆与留存」;
- 都复用现有逐块分析产物,不动 OCR/AI 主链路;
- 三者环环相扣:设级别 -> 智能决定哪些词值得收 -> 收进生词本 -> 导出 Anki 去刷。

地基问题(第 4 项,字典校验标注)可作为这条线的子任务一并解决,让级别过滤真正可信。

### 建议拆分为可独立交付的里程碑

- **里程碑 1(第一部分)**:个人词汇本 + 一键收藏 + 生词本视图。建立缺失的数据模型与持久化,任何后续功能(级别过滤、SRS、导出)都建立在「能收词」之上。先不依赖级别校准,允许收藏任意词。
- **里程碑 2**:目标级别设置 + 级别感知过滤(含字典校准,修地基),让收藏/展示按级别智能化。
- **里程碑 3**:Anki / CSV 导出 + 基础 SRS 复习,把收进来的词变成可复习、可带走。
